## 📌 1. 개요
AI 및 에이전트 기반 코딩(바이브 코딩) 시 빈번하게 발생하는 **과도한 결제(토큰 폭주), 데이터 유출, 권한 남용, 보안 취약점**을 사전에 차단하기 위한 8가지 핵심 안전 설정 및 대응 지침이다.

---

## ⚙️ 2. 핵심 위험 요소 및 해결 지침 8가지

### 1. API 결제 월 상한선 (Monthly Maximum) 설정
- **위험**: 자동 충전(Auto-reload) 무제한 설정 시 에이전트 무한 루프로 수십~수백만 원 과금 발생.
- **해결**: AI 콘솔(`Settings > Billing > Auto-reload`)에서 **월 사용 한도(예: 10만 원)**를 지정하거나 자동 충전 비활성화.

### 2. 에이전트 동시 실행 수 및 기본 모델 제한
- **위험**: 서브에이전트 재귀 호출로 수백 개 증식 및 고비용 모델 상속으로 토큰 낭비.
- **해결**: 가벼운 작업은 `flash`/`flash_lite` 등 경량 모델로 고정하고 동시 실행 에이전트를 최대 3~5개로 제한.

### 3. 무조건 자동 승인(Auto-Approve) 금지 & 파괴적 명령 격리
- **위험**: 무차별 자동 승인 시 부모 폴더 통째 삭제(`rm -rf`) 또는 외부 악성 스크립트의 파일 탈취 위험.
- **해결**: 삭제 및 시스템 변경 명령은 반드시 사용자 검증을 거치고, 작업 경로를 프로젝트 폴더 내부로 엄격히 한정(샌드박스화).

### 4. 데이터베이스 백업 분리 및 복구 테스트
- **위험**: 원본 DB와 동일 저장소에 백업 시 AI 정리 작업으로 백업본까지 동시 영구 소실.
- **해결**: 백업은 원본과 다른 계정/독립 스토리지에 저장하고, 실제 데이터가 열리는지 **복구 테스트(Restore Drill)**를 사전 검증.

### 5. API 키 최소 권한(Least Privilege) & 만료 기한 부여
- **위험**: 단일 기능용 키에 마스터 권한(Admin) 부여 시 우회 경로를 통해 DB 전체 삭제/탈취 위험.
- **해결**: 최소 권한만 부여하고 짧은 만료 기한을 설정하며, 작업 완료 즉시 키 폐기.

### 6. Supabase / PostgreSQL RLS (행 단위 보안) 필수 활성화
- **위험**: AI가 회원 기능 코드는 작성하지만 DB의 RLS를 켜지 않아 브라우저 anon key만으로 전 회원 개인정보(이메일, 신분증 등) 무단 열람 가능.
- **해결**: 테이블 생성 시 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` 및 RLS 정책(Policy)을 기본 필수 적용.

### 7. 프론트엔드/GitHub 시크릿 키(Secret Key) 노출 금지
- **위험**: 브라우저 JS 코드나 공개 커밋에 결제/Admin 키 하드코딩 노출로 대량 호출 도용.
- **해결**: 시크릿 키는 반드시 서버 환경변수(Edge Function Secrets 등)에 보관. 이미 노출된 키는 즉시 폐기 후 재발급.

### 8. 코드 생성 시 보안 검증 기본 내장
- **위험**: AI 생성 코드의 약 45%가 기본 취약점을 포함하고 있으나 무검증 배포.
- **해결**: 프롬프트 시 "인증 및 입력값 검증(Validation) 포함"을 지시하고, 배포 전 정적 분석 및 보안 취약점 사전 점검.

## 🛠️ 3. Antigravity 시스템 적용 사항
1. **코드 생성 표준**: Supabase/PostgreSQL 사용 시 RLS 활성화 및 Zod/Pydantic 검증 로직 기본 삽입.
2. **시크릿 키 보호**: 클라이언트 파일에 키 하드코딩 금지, `.env` 및 `.gitignore` 설정 자동 점검.
3. **파괴적 작업 방지**: `accidental-data-loss-prevention` 스킬에 따라 대량 삭제/DROP 전 사용자 명시적 승인 준수.
4. **서브에이전트 비용 최적화**: 경량 리서치는 `flash` 모델 활용 및 동시 실행 제한.
