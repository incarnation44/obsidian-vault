## 💡 핵심 3줄 요약
1. **단방향 챗봇의 종말**: 텍스트를 치고 답변을 기다리는 턴제(Turn-taking) 챗봇에서 벗어나, 말하는 도중 끊기(Interruption)가 가능한 양방향 실시간(Bidirectional Live) 옴니 앱으로의 진화.
2. **3대 핵심 루프 (Perceive -> Reason -> Express)**: 음성·카메라·화면을 동시에 감지(Perceive)하고, 도구를 판단(Reason)하며, 음성 출력과 브라우저 제어로 행동(Express)하는 연속 루프 구조.
3. **6대 필수 구현 스택**: 실시간 음성(Live Voice) -> 컨베이어 프레임워크(ADK/SDK) -> 침묵 없는 도구 호출(Tool Latency) -> 브라우저 제어(Browser Hands) -> 하이브리드 메모리 -> 적응형 비전(Vision Streams).

## 🏗️ 6대 핵심 구축 스택 (Season 1 Roadmap)

### 1. Episode 1: 실시간 음성 (Live Voice vs TTS)
- **TTS(Text-to-Speech)의 한계**: 글을 읽어줄 뿐 사용자의 말을 동시에 들을 수 없음.
- **Live Voice의 혁신**: 세션이 열려 있는 동안 모델이 계속 듣고 있으며, 모델이 말하는 중간에 사용자가 말을 끊고 끼어들기(Interruption) 가능. 녹음기가 아닌 실제 대화 느낌 제공.

### 2. Episode 2: 프레임워크 및 컨베이어 벨트 (Google ADK / JS SDK)
- **컨베이어 벨트 멘탈 모델**: 브라우저 마이크가 끊임없이 오디오 청크를 컨베이어 한쪽에 올리고, AI 모델이 반대편에서 즉각 소비하며 이벤트와 음성을 동시에 뿜어내는 구조.

### 3. Episode 3: 침묵 없는 도구 호출 (Tool Latency 최적화)
- **라이브 보이스의 최대 적**: 툴 호출 시 수 초간 발생하는 어색한 침묵.
- 모델이 생각하고 외부 함수(음악 재생, 검색, 결제 등)를 호출하는 동안 대화 맥락이 끊기지 않는 비동기 응답 처리 전략.

### 4. Episode 4: 브라우저 제어 핸즈 (Browser Hands)
- 사용자의 음성 지시를 듣고 실시간으로 웹페이지(아마존 검색, 쇼핑, 음악 조작 등)를 보면서 브라우저를 직접 클릭하고 탐색하는 Voice-to-Browser 컨트롤 파이프라인.

### 5. Episode 5: 하이브리드 메모리 시스템 (Memory)
- 실시간 대화 흐름을 방해하지 않고 팩트 데이터(정형 데이터)와 문맥 벡터(Vector DB)를 초고속으로 조회(Retrieve)하여 사용자 맞춤 기억 유지.

### 6. Episode 6: 적응형 비전 스트림 (Vision & Snapshot)
- 단일 스냅샷(정확하지만 지연)과 연속 비디오 프레임(맥락 유지하지만 토큰/네트워크 부담) 간의 균형 설계.

## 🛠️ AI(나/Antigravity)에게 즉시 적용할 점

1. **WebMCP 기반 브라우저 백그라운드 제어 연계 (Browser Hands)**
- 영상의 Browser Hands 철학을 반영하여, 향후 웹 자동화나 실시간 탐색 요청 시 Playwright Headless 도구와 인페이지 WebMCP 계약을 결합하여 백그라운드에서 실시간 탐색·작업을 자율 수행.
2. **침묵 방지형 인터페이스 피드백 파이프라인 (Tool Latency Safe)**
- 대규모 코드 생성이나 복잡한 RAG 탐색 등 지연 시간이 발생하는 도구 호출 시, 프로세스 진행 상태를 즉각 피드백하고 비동기 백그라운드 태스크로 분리하여 컨텍스트 대기 지연을 최소화.
3. **영구 하이브리드 메모리 (memory.db) 융합**
- 영상의 Episode 5(Memory) 원칙을 따라 사용자의 기기 사양, 시스템 선호도, 과거 의사결정(ADR)을 memory.db와 옵시디언 볼트에 구조화하여 세션이 초기화되어도 즉시 복원되는 옴니 컨텍스트 유지.
