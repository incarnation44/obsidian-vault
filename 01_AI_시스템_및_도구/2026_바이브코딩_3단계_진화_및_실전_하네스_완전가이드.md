## 💡 핵심 3줄 요약

1. **개발 패러다임의 3단계 진화**: 프롬프트 엔지니어링(말 잘하기) → 컨텍스트 엔지니어링(규칙 주기) → **하네스 엔지니어링(자가 치유 환경 구축 - 2026 핵심)**으로 무게중심 이동.
2. **2026 최적 기술 스택**: 웹은 `Next.js + Supabase + Vercel`, 모바일은 `Expo + Firebase`, 데스크톱은 경량 `Tauri` 조합이 표준.
3. **카파시 4대 코딩 가이드라인**: ① 가정/트레이드오프 공개 ② 군더더기 금지 ③ 외과수술적 최소 수정 ④ 성공 검증 기준 설정.

## 📌 주요 내용 및 핵심 분석

### 1. 바이브 코딩 패러다임 3단계 진화
* **1단계: 프롬프트 엔지니어링 (말 잘하기)**
  - 프롬프트를 구체적으로 쓰면 결과가 좋아진다는 발상. (한계: 프로젝트 전체 맥락과 규칙을 매번 다 적을 수 없음)
* **2단계: 컨텍스트 엔지니어링 (맥락 채우기)**
  - `CLAUDE.md`, 규칙 파일, 코드베이스를 미리 주입하여 일관성 확보. (한계: 모델이 직접 실행·테스트·검증하지 못함)
* **3단계: 하네스 엔지니어링 (2026 핵심: 환경 만들기)**
  - 모델(엔진)에 핸들, 브레이크, 계기판을 달아주는 시스템.
  - **자동 자가치유 루프**: AI가 코드를 작성 → 자동 테스트 실행 → 에러(빨간불) 발생 시 AI가 스스로 수정 → 정상(초록불) 뜰 때까지 반복 완결.

### 2. 2026 플랫폼별 실전 권장 기술 스택

| 플랫폼 | 추천 프론트엔드 | 백엔드 / DB | 배포 / 빌드 | 특징 및 선택 이유 |
| :--- | :--- | :--- | :--- | :--- |
| **웹 (Web)** | **Next.js** | **Supabase** | **Vercel** | 빠른 개발, 풍부한 문서, 1인 풀스택 표준 |
| **모바일 (Mobile)** | **Expo (React Native)** | **Firebase / Supabase** | **EAS** | iOS/Android 크로스플랫폼 단일 코드 개발 |
| **데스크톱 (Desktop)** | **Tauri** (or Electron) | 로컬 파일 / SQLite | Native | 타우리는 용량이 매우 가볍고 초경량 고성능 |

### 3. 카파시(Karpathy) 코딩 4대 핵심 가이드라인

1. **가정과 트레이드오프 선공개**: AI가 혼자 추측해서 코드를 짜지 않고, 어떤 전제로 개발하는지 먼저 드러낼 것.
2. **군더더기(Over-engineering) 배제**: 요청하지 않은 불필요한 추상화나 과도한 코드를 만들지 말 것.
3. **외과수술적 수정 (Surgical Edit)**: 전체 코드를 무차별 덮어쓰지 않고 변경 대상 라인만 정밀하게 핀셋 수정할 것.
4. **성공 검증 기준 마련**: 코드가 정상 동작하는지 테스트/검증할 수 있는 명확한 기준을 둘 것.

## 🛠️ AI(나: Antigravity)에게 적용할 점

1. **카파시 외과수술적 수정 원칙 (`replace_file_content` 최적화)**:
   - 파일 전체를 불필요하게 덮어쓰지 않고, 수정이 필요한 코드 블록만 정확히 타깃팅하여 무결성 유지 및 토큰 절약.
2. **에이전틱 평가 하네스 루프 실전 가동**:
   - 코드 작성 후 반드시 터미널 명령을 통해 빌드 및 문법 검증을 직접 수행하고, 오류 발생 시 스스로 즉각 디버깅하여 오류 없는 결과만 사용자에게 보고.
3. **표준 3대 스택 스캐폴딩 지원**:
   - 사용자 웹/앱 개발 요청 시 `Next.js/Vite + Supabase + Vercel` 표준 구조를 즉시 자동 스캐폴딩.
