# Egolight - AI 에이전트 전용 브라우저 분석과 Headless Playwright 비교

- 원본 출처: https://youtu.be/uy5XmijKOUA

## 💡 핵심 3줄
1. Egolight는 기존 Playwright 자동화 시 발생하는 창 팝업, 커서 탈취, 에이전트 간 세션 충돌을 해결하기 위해 **'스페이스(Space) 기반 독립 격리'**를 제공하는 무료 AI 전용 크로미엄 브라우저다.
2. 실제 사용자 로그인 세션(쿠키)을 유지하여 API가 없는 대시보드(유튜브 스튜디오 등)나 복잡한 예약 사이트를 다중 에이전트가 백그라운드에서 병렬 자동화할 수 있다.
3. 우리 Antigravity는 이미 **'100% Headless(창 없는 백그라운드) Playwright'** 원칙을 고수하여 포커스 탈취 문제가 없으므로, **지금 당장 브라우저를 교체할 필요는 없으며 '세션 유지 및 Takeover 패턴'만 지식으로 보존**한다.

## 📌 1. Egolight 핵심 기능 및 기존 자동화 도구 한계 해결

### ① 기존 Playwright / Chrome 자동화의 고질적 페인포인트
- **화면 간섭 & 포커스 탈취**: 에이전트가 브라우저를 띄우면 마우스 커서와 화면 포커스를 빼앗아 가 작업 중단 초래.
- **에이전트 간 오너십 충돌**: 멀티 에이전트 환경에서 동일 브라우저 인스턴스를 공유하다가 세션이 꼬임.
- **세션 휘발**: 매번 새 브라우저 컨텍스트가 열려 로그인 상태가 풀리고 캡차(CAPTCHA)에 걸림.
- **창 정리 실패**: 작업 후 프로세스가 정리되지 않고 백그라운드에 누적.

### ② Egolight의 핵심 차별화 4요소
1. **스페이스(Space) 단위 격리**: 에이전트별/작업별로 독립 가상 브라우저 공간을 배정하여 병렬 실행 시 상호 간섭 원천 차단.
2. **무간섭 백그라운드 제어**: 사용자의 실제 화면이나 커서에 간섭하지 않고 독립적으로 DOM 조작.
3. **인간 개입 지원 (Takeover & Return to Agent)**: 캡차나 본인인증 필요 시 사람이 즉시 통제권을 가져와 처리하고 다시 AI에게 제어권 반환.
4. **영구 세션/쿠키 유지**: 크로미엄 기반 브라우저로 로그인 상태를 상시 유지하여 비공개 데이터(유튜브 스튜디오, 관리자 페이지) 스크래핑 용이.

## 📊 2. 현재 Antigravity 환경과의 비교 분석

| 비교 항목 | Egolight (영상 소개 도구) | Antigravity 현재 스택 (Playwright Headless) | 판정 및 권고 |
| :--- | :--- | :--- | :--- |
| **화면 표시** | GUI 브라우저 (스페이스 분리) | **100% Headless (창 팝업 원천 차단)** | 우리 헌법 규칙에 이미 부합 (창 팝업 금지) |
| **마우스/포커스 간섭** | 없음 (가상 스페이스 제어) | **전혀 없음 (창 자체가 안 뜸)** | 둘 다 해결됨 |
| **로그인 세션 유지** | 실제 크로미엄 프로필 쿠키 유지 | 기본 일회성 컨텍스트 (필요 시 쿠키 주입) | 로그인 필요 작업 시 Egolight가 유리 |
| **시스템 리소스 소모** | 크로미엄 인스턴스 상주로 RAM 증가 | 가벼운 Node/Python Headless 프로세스 | **우리 시스템이 훨씬 가볍고 자원 절약적** |
| **현재 도입 필요성** | 별도 브라우저 앱 설치 필요 | 이미 MCP 활성화 상태 | ❌ **현재 상태에서 도입 불필요 (중복)** |

## ⚙️ 3. Antigravity 시스템 적용 검토

1. **기존 시스템 대비 중복 여부 (현재 상태에서 굳이 필요 없음)**:
   - **중복/불필요**: GEMINI.md 헌법 규칙 4번에 따라 우리는 브라우저 조작 시 100% Headless(백그라운드) 모드를 강제하고 있으므로 커서가 튀거나 창이 화면을 가리는 문제가 애초에 발생하지 않습니다.
   - 또한 웹 문서나 유튜브 요약 등은 `read_url_content`와 `youtube-transcribe` 전용 API로 훨씬 빠르고 가볍게 처리하고 있으므로 무거운 브라우저 프로그램을 추가할 필요가 없습니다.

2. **설계적으로 흡수할 인사이트 (비즈니스 자동화 시)**:
   - 향후 `D:\KH_AI` 관련하여 **로그인이 필수적인 기업용 웹 콘솔 자동화나 캡차 우회, 대시보드 데이터 수집**이 필요한 특수 태스크가 생길 때, "쿠키 세션 보존 + 사람 개입(Takeover)" 패턴은 검토해 볼 만한 가치가 있습니다.

3. **기기별 하드웨어 사양 고려**:
   - **메인 데스크톱 (RX 6600 8GB / 32GB RAM)**: 크로미엄 기반 브라우저를 여러 개 띄우면 수 GB 단위의 RAM을 추가 점유하므로, 순수 Headless 모드가 시스템 자원 보존에 적합합니다.
   - **서브 노트북 (Dell Latitude 7440 / Iris Xe 내장그래픽)**: 상주형 브라우저 프로그램 구동 시 CPU 부하와 배터리 소모가 심하므로 설치를 권장하지 않습니다.
