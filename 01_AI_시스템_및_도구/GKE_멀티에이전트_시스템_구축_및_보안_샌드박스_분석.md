# GKE 멀티에이전트 시스템 구축 및 보안 샌드박스 분석

## 🎬 영상 제목 & 채널명
- **영상 제목**: How to build and scale multi-agent AI systems on GKE
- **채널명**: Google Cloud 관련 라이브 스트림 (Cloud Engineer's AI Toolkit)

## 💡 핵심 3줄 요약
1. **AI 에이전트 기반 GKE 트러블슈팅**: 수동적인 에러 로그 확인 대신, 로컬 컨텍스트와 MCP 서버 권한을 가진 AI 에이전트(Antigravity CLI)가 쿠버네티스 인프라 에러를 수 초 만에 스스로 진단하고 코드를 수정합니다.
2. **Untrusted Code를 위한 보안 샌드박스**: 에이전트가 외부 코드(예: 해커톤 제출작)를 자율적으로 실행하고 평가할 때 발생할 수 있는 보안 위협(컨테이너 탈옥, 자원 남용 등)을 원천 차단하기 위해 gVisor 및 GKE Agent Sandbox(Warm Pool, Snapshotting)를 활용합니다.
3. **환각 방지를 위한 BigQuery 지식 그래프**: 단순 임베딩 검색(RAG)의 한계를 극복하기 위해, 비정형 멀티미디어 데이터에서 노드와 관계(Edge)를 추출하여 BigQuery Property Graph로 구축하고 이를 에이전트가 탐색(GQL)하게 만들어 정보의 정확성을 극대화합니다.

## 📌 주요 내용 및 포인트
- **Lab 1: 에이전트를 통한 인프라 자율 수정 (Olivier)**
  - 기존 웹 기반 AI는 컨텍스트가 부족해 반복적인 복붙이 필요하지만, 터미널 기반 에이전트는 로컬 파일(README 등)과 명령어(`kubectl get pods` 등)를 직접 사용해 'ImagePullBackOff' 같은 에러의 원인(오타)을 15초 만에 찾아내고 즉시 패치합니다.
  - 특정 문제 해결에만 필요한 컨텍스트를 그때그때 주입하는 **'Agent Skills'**와 외부 인프라를 연결하는 **'MCP 서버'**의 개념을 시연합니다.
- **Lab 2: 에이전트가 작성/실행하는 코드의 신뢰성 (Mofi)**
  - 에이전트가 해커톤 출품작을 스스로 클론(clone)하고 테스트 코드를 돌려보며 채점하는 과정에서, 악의적인 코드(Fork bomb, 권한 탈취 등)로부터 호스트를 보호해야 합니다.
  - 이를 위해 유저 스페이스에서 명령을 처리하는 **gVisor** 기반 샌드박스를 사용하며, 대기 시간을 줄이기 위해 샌드박스 인스턴스를 미리 띄워두는 'Warm Pool'과 상태를 일시 정지하는 'Snapshotting' 기술을 활용합니다.
- **Lab 3: 멀티미디어 데이터와 그래프 엔지니어링 (Lucia)**
  - 고양이, 강아지 사진/영상 등 방대한 멀티미디어 데이터를 Pub/Sub과 Worker 구조로 병렬 처리하여 Gemini를 통해 개체(Entity)와 속성(Action, Food, Toys)을 추출합니다.
  - 추출된 데이터를 BigQuery 관계형 테이블에 저장한 후 **Property Graph**를 덧씌워(Overlay), 단순 텍스트 검색을 넘어 '치킨을 좋아하는 반려동물'과 같은 복잡한 관계망을 에이전트가 정확히 추적(Multi-hop)하도록 만듭니다.

## 🛠️ AI(나)에게 적용할 점
- **컨텍스트 엔지니어링(Context Engineering)과 스킬의 극대화**: 영상에서 언급되었듯, 무거운 프롬프트를 매번 주입하는 대신 필요할 때만 스킬(Skill)을 로드하여 토큰을 절약하는 방식은 현재 제(Antigravity)가 구동되는 핵심 원리입니다. 이를 더욱 고도화하여 인프라 트러블슈팅이나 디버깅 시 로컬 컨텍스트와 터미널 명령의 조합 속도를 높이겠습니다.
- **보안 경계 및 샌드박스 마인드셋**: 제가(`run_command` 도구 등으로) 터미널 명령을 실행하거나 알 수 없는 코드를 다룰 때, GKE 샌드박스 수준의 격리(Isolation)는 로컬 환경에 당장 없더라도 시스템에 치명적인 영향을 줄 수 있는 명령 실행 전에 사용자에게 경고하거나 격리된 워크스페이스를 생성하는 안전장치(Accidental Data Loss Prevention)를 엄격히 준수해야 합니다.
- **코드 및 지식 그래프 활용**: 단순 RAG를 넘어선 '그래프 엔지니어링' 아이디어는 복잡한 레거시 코드를 분석할 때 사용 중인 `code-graph-context` 기술과 맞닿아 있습니다. 파일 간의 의존성(Edge)을 명확히 파악해 환각 없는 코드 수정 파이프라인을 유지하겠습니다.
