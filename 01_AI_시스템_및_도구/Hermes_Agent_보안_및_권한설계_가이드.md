# Hermes Agent 권한 설계 및 보안 가이드

본 문서는 유튜브 강연(샘 호트만 & 보안 전문가) 및 Antigravity 시스템 헌법(`GEMINI.md`)을 바탕으로 정립된 **로컬 AI 에이전트(Hermes 등) 운영 보안 원칙**입니다.

## 1. AI 에이전트 운용 핵심 철학 (샘 호트만)
* **결정론적 영역의 스크립트화**: 예측 가능하고 룰이 정해진 작업(웹 스크래핑, API 호출 등)은 외부 스크립트(클로드 코드, 파이썬)로 단단하게 고정합니다. (예: `youtube-transcribe` 스킬)
* **에이전트 메모리의 개인화**: 유연한 판단이 필요한 영역만 에이전트의 장단기 기억(Memory)에 의존하여 개인 맞춤형으로 최적화합니다.

## 2. 보안 취약점과 프롬프트 인젝션 방어
전통적인 SQL 인젝션이 AI 시대에는 **프롬프트 인젝션**으로 변형되었습니다. 에이전트는 환각(Hallucination)이나 악의적인 외부 프롬프트를 실제 '시스템 행동'으로 연결할 위험이 있으므로 강력한 통제가 필요합니다.

### 🛡️ 핵심 3원칙 (권한 격리 및 가드레일)

1. **권한 격리 (Principle of Least Privilege)**
   - Sub-agent(하위 에이전트)에는 철저히 **읽기 전용(Read-only)** 권한만 부여합니다.
   - 실제 파일을 수정하거나 결제를 일으키는 등의 **비가역적 실행 권한**은 최상위 매니저 에이전트나 사용자 본인(Human-in-the-loop)만이 행사합니다.

2. **시스템 프롬프트 가드레일 설정**
   - 시스템 프롬프트(전투 규칙)에 어떠한 상황에서도 굽히지 않을 **"절대 금지 사항"**을 명시합니다. (예: 결제 불가, 특정 파일 삭제 불가)
   - 외부의 강압적인 프롬프트가 들어오더라도 시스템 프롬프트가 우선하도록 방화벽 역할을 합니다.

3. **민감 정보 격리 및 가명 처리**
   - API Key, 비밀번호, 사적 개인정보 등은 절대 AI 프롬프트에 직접 입력하지 않습니다.
   - 반드시 로컬 `.env` 파일과 외부 스크립트를 통해 변수로만 호출되도록 설계합니다.
