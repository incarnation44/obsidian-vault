## 💡 핵심 요약 (Level 0)

* **해결하려는 핵심 문제**: 개별 전문 에이전트(리서치팀, 유튜브팀, 교육팀)를 만들어도, 작업 결과물을 복사해서 다음 에이전트에게 넘겨주는 **인간이 시스템의 최대 병목(Bottleneck)**이 되는 문제 해결.
* **해결책 (칸반 기반 비동기 오케스트레이션)**:
  * 사람이 중간 전달자 역할을 하지 않고, **칸반 보드(Kanban Board) 상태 머신**과 **부모-자식 작업 의존성(DAG)**을 통해 에이전트끼리 자율적으로 바통을 넘기는 무인 파이프라인 구축.
* **핵심 아키텍처**:
  1. **칸반 보드 상태 전이**: `TODO` ➔ `PENDING(대기)` ➔ `READY(실행준비)` ➔ `IN_PROGRESS(진행중)` ➔ `DONE(완료)` / `FAILED(실패)`.
  2. **결정론적 디스패처 (Deterministic Dispatcher)**: 복잡한 LLM 추론이 아닌, 60초 주기의 경량 파이썬 실행 엔진이 부모 작업의 `DONE` 상태를 감지하여 후속 자식 작업을 `READY`로 자동 승격.
  3. **AgentReach 스킬**: 단순 웹 검색이 아닌 X(Twitter), Reddit 등 개발자 커뮤니티의 실시간 반응과 트렌드를 수집하는 전용 도구 연동.

## 🏗️ 1. 칸반 멀티에이전트 파이프라인 3대 핵심 구조

### ① 인간 병목의 제거 (인간은 단일 목표만 등록)
* 사용자는 아침에 "오늘의 AI 핵심 트렌드 기반 콘텐츠 생성"이라는 단 하나의 최상위 목표(Goal)만 등록.
* 기획 단계에서 하위 작업(리서치 ➔ 숏츠 대본 작성 & 슬라이드 제작)을 분해하고 부모-자식 의존성(Dependency)을 카드로 자동 발행.

### ② LLM과 결정론적 코드(Dispatcher)의 엄격한 역할 분리
* **안티패턴**: 작업 배정, 상태 변경, 알림 등 단순 상태 관리를 거대 LLM에게 맡기면 환각과 누락이 발생하고 비용이 낭비됨.
* **정석 설계**: 
  * 작업 상태 전이 및 스케줄링은 100% **결정론적 코드(Dispatcher Daemon)**가 처리.
  * LLM은 오직 '작업 수행(Research, Scripting, Code)'에만 집중 투입.

### ③ 비동기 병렬 트리거 (Fan-Out Execution)
* 리서치 팀의 작업 카드가 `DONE`으로 이동하는 즉시, 이를 선행 조건으로 삼고 있던 '유튜브 숏츠 팀'과 '강의 슬라이드 팀'이 동시에 병렬 구동.
* 사용자가 잠든 새벽에도 크론(Cron) 스케줄러를 통해 전 과정이 자율 완결됨.

## 🔍 2. 우리 시스템(Antigravity) 대조 및 5-Gate 평가

| 설계 요소 | 후츠릿의 Hermes 칸반 시스템 | 우리 시스템 (Antigravity & GEMINI.md) |
| :--- | :--- | :--- |
| **작업 상태판** | 파일/DB 기반 칸반 보드 카드 | `PROJECT_STATUS.md` & `implementation_plan.md` |
| **상태 관리 주체** | 60초 주기 파이썬 디스패처 (No-LLM) | 8단계 폐쇄 루프 (`GOAL ➔ ... ➔ DECIDE ➔ REPORT`) |
| **작업 격리 및 실행** | Hermes 개별 프로필 세션 분기 | `invoke_subagent` 및 컨텍스트 외과수술적 격리 |
| **추론 vs 결정론 분리** | LLM(생성) + 디스패처(규칙 전이) | LLM(판단) + 결정론적 헌법/스크립트 분리 |

### ⚖️ 5-Gate 판별 및 의사결정: `ADAPT (원칙 흡수) / NO CODE CHANGE`
1. **실제 문제인가?**: 멀티 세션 작업 시 인간이 복사-붙여넣기 병목이 되는 현상은 다중 작업 시 실재함.
2. **기존 기능으로 해결 가능한가?**: Antigravity의 `PROJECT_STATUS.md` 파일 상태판과 `invoke_subagent` 백그라운드 태스크 메커니즘으로 이미 완전히 해결 가능.
3. **추가 복잡성 대비 효과**: 별도의 칸반 보드 서버나 Hermes 전용 스택을 추가하는 것은 [FREEZE] 원칙 위반이자 불필요한 복잡성 초래.
4. **결정**: **`NO CODE CHANGE` (시스템 변경 없음)**.  
   - "상태 전이는 결정론적 코드로, 작업 수행은 LLM으로"라는 아키텍처 철학은 이미 우리 헌법에 반영되어 있으므로, 신규 프레임워크 설치 없이 현재 시스템을 유지함.
