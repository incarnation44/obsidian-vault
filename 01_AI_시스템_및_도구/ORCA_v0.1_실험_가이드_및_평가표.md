## 📋 2. 단계별 실험 시나리오

### 🔹 1단계: 순수 성능 비교 (작업 1 ~ 2)
* **방식**: 동일 버그/기능에 대해 동일 프롬프트로 각각 독립 Worktree에서 실행 후 A/B 비교
* **수행 지침**:
  1. 원인을 분석한다.
  2. 필요한 파일만 수정한다.
  3. 기존 테스트를 실행하고, 필요한 테스트를 추가한다.
  4. 변경한 파일과 이유를 요약한다.

### 🔹 2단계: 실제 병렬 분업 처리 (작업 3 ~ 5)
* **방식**: 서로 다른 역할을 나누어 처리하여 실제 생산성 확인
  * `Codex`: 메인 코드 구현 및 기능 수정
  * `Claude Code`: diff 리뷰 및 회귀 테스트 보강
  * `Ollama (로컬)`: 로그 분석 및 프로젝트 구조 사전 조사
* **🔄 반려 피드백 자동 재시도 루프 (Feedback Loop)**:
  * 리뷰 단계(Claude Code 또는 사람)에서 반려(Reject) 시: **[직전 코드/산출물 + 반려 피드백]**을 묶어 Codex에게 전달
  * Codex는 전체를 다시 짜지 않고 지적받은 문제점만 핀포인트로 수정 후 재검토 요청 (최대 3회 제한)

## 🎯 4. 최종 판단 기준 (1~2주 후)

* **✅ ORCA 유지 및 v0.2(간이 라우터/파이프라인) 진행 기준**:
  * 5개 작업 중 **3개 이상**에서 병렬 Agent 사용으로 **결과 품질이 향상**되거나, **작업 시간 및 사람의 수정 개입이 눈에 띄게 단축**된 경우.
* **❌ ORCA 과감히 제거 기준**:
  * 두 에이전트 결과물이 대동소이하고, diff 비교 및 병합하는 데 시간이 더 오래 걸려 피로도가 높아지는 경우.
