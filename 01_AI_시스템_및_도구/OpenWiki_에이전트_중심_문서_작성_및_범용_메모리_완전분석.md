# 🤖 OpenWiki: 사람이 아닌 AI 에이전트를 위한 문서 작성법과 범용 메모리

> "사람이 코드를 직접 쓰지 않는 시대라면, 저장소 문서 또한 사람이 아닌 에이전트가 소비하도록 최적화되어야 한다."

---

## 💡 핵심 3줄 요약
1. **에이전트 전용 문서(Agent-First Docs)**: 에이전트는 긴 서론이나 스토리텔링 대신 파편(Snippet)을 검색하므로, 모든 문서는 단편 독립적(Self-contained)이어야 하며 명확한 헤딩과 Google OKF(Open Knowledge Format) 프론트매터를 필수로 갖춰야 한다.
2. **카파시 LLM Wiki & 완전 자동 유지보수**: `quickstart.md`, `index.md`, 변경 로그(`log.md`) 구조를 채택하고, GitHub Actions 크론을 통해 Git 커밋 히스토리를 추적하여 문서를 알아서 자가 갱신한다.
3. **벤치마크 검증 및 다이어그램의 부활**: 툴 호출 횟수와 토큰 소모를 대폭 줄이면서 작업 성공률을 높였고, 초기 텍스트 중심에서 시퀀스·플로우차트 다이어그램을 보강하여 개발자 가독성과 에이전트의 구조 이해도를 동시에 끌어올렸다.

---

## 📌 주요 내용 및 핵심 아키텍처

### 1. 개발 배경과 '범용 메모리(General Purpose Memory)' 철학
* **AI의 다음 격전지**: LangChain CEO 해리슨 체이스의 질문("AI 분야의 다음 메가 트렌드는 무엇인가?")에 대한 답은 **'범용 메모리'**였다.
* **코드베이스 문서부터 출발**: 완전한 범용 메모리를 구축하기 전, 가장 명확하게 정의할 수 있는 영역인 **코드베이스 레포지토리 문서**를 첫 번째 타깃으로 선정했다.
* **소비 주체의 전환**: 현대 개발 환경에서 코드를 작성하고 탐색하는 주체는 인간이 아닌 AI 에이전트다. 따라서 문서는 인간 중심(스토리, 튜토리얼)에서 에이전트 중심(파편 검색, 토큰 효율)으로 재설계되어야 한다.

---

### 2. 인간용 문서 vs 에이전트용 문서 비교

| 구분 | 인간을 위한 문서 (Human-First) | 에이전트를 위한 문서 (Agent-First) |
| :--- | :--- | :--- |
| **소비 방식** | 처음부터 끝까지 흐름을 따라 순차 정독 | 필요한 파편(Snippet)만 핀셋 검색 및 주입 |
| **구조적 특성** | 배경 설명, 비디오, 스크린샷 위주 | **독립적(Self-contained)** 단락, 정밀한 헤딩 |
| **토큰/포맷** | 줄글, Base64 이미지 등 노이즈 허용 | 컨텍스트 윈도우 최적화, 불필요한 토큰 배제 |
| **색인/메타** | 목차(TOC) 수준 | **Google OKF 정형 프론트매터 (`type`, `tags`)** |

---

### 3. Google OKF (Open Knowledge Format) 표준 채택
에이전트가 방대한 코드베이스 문서를 검색할 때 환각을 줄이고 정확한 타깃을 찾도록 **OKF 정형 메타데이터**를 마크다운 상단에 강제한다.

```yaml
---
type: architecture-doc       # 문서 분류 (architecture, api, workflow 등)
title: Auth Flow Engine      # 정밀한 제목
description: JWT 토큰 갱신 로직  # 1줄 핵심 요약
resource_tags:              # 연결된 실제 코드 파일 경로
  - src/auth/jwt.ts
  - src/middleware/auth.ts
timestamp: 2026-08-18T21:00:00Z
---
```
* **결과**: 에이전트가 "인증 관련 아키텍처 문서를 가져와"라고 할 때 전체 문서를 다 뒤지지 않고 `type: architecture-doc`과 `resource_tags`로 즉시 필터링한다.

---

### 4. 구조 설계: Karpathy 스타일 LLM Wiki
* **`quickstart.md`**: 저장소의 핵심 개념과 주요 컴포넌트 지도를 에이전트에게 1차 주입.
* **`index.md`**: 디렉터리별 하위 문서 목록 색인.
* **`log.md` (Change Log)**: 최근 Git 커밋으로 어떤 문서가 수정·추가되었는지 요약. 에이전트와 인간 개발자 모두에게 변경 이력 추적점을 제공.
* **상호 마크다운 링크 (`[[Doc]]`)**: 문서 간 cross-link를 통해 에이전트가 연관 맥락을 스스로 타고 들어갈 수 있도록 유도.

---

### 5. 자가 갱신 파이프라인 (`openwiki init` / `openwiki update`)
* **초기 설정 (`init`)**: 모델 및 키 설정 후 저장소의 전체 파일과 **Git 히스토리(커밋 메시지, diff)**를 분석하여 초기 위키 생성.
* **자동 갱신 (`update`)**: GitHub Actions에 매일 도는 크론을 등록. 마지막 실행 이후 변경된 커밋 로그만 파싱하여 바뀐 부분만 위키에 반영하고 자동으로 PR을 생성.
* **다이어그램의 역할 재발견**: 초기에는 순수 텍스트만 넣었으나, 인간 엔지니어의 피드백을 반영해 **Mermaid 시퀀스/상태 다이어그램**을 추가. 결과적으로 개발자뿐 아니라 에이전트의 워크플로우 추론 정확도도 개선됨.

---

### 6. 벤치마크 결과 (Deep Sweet 코딩 벤치마크)
* **툴 호출 횟수 감소**: 불필요한 파일 탐색 명령(`grep`, `find`) 최소화.
* **토큰 소비 대폭 절감**: 핵심 파편만 주입하여 컨텍스트 창 낭비 방지.
* **작업 성공률 상승**: 기존 대비 더 높은 과제 해결률 기록.

---

## 🛠️ AI(나, Antigravity)에게 적용할 점

1. **옵시디언 볼트(`C:\전일도`) 문서의 OKF 메타데이터 표준화**
   * 볼트에 새로 생성하거나 업데이트하는 모든 기술/시스템 노트 상단에 `type`, `title`, `description`, `resource_tags`를 명확히 기록한다.
   * `chunkless-rag` 및 에이전트 검색 시 불필요한 토큰 소모를 막고 핀셋 검색 적중률을 극대화한다.

2. **작업 산출물에 `log.md` 형태의 변경 이력(Delta) 필수 제공**
   * 대규모 리팩토링이나 문서 정리 시 변경된 핵심 파일과 이유를 변경 로그 형태로 요약 보고하여, 다음 세션에서 에이전트가 이전 컨텍스트를 즉시 복원할 수 있도록 한다.

3. **텍스트 설명과 Mermaid 다이어그램의 하이브리드 결합**
   * 단순 줄글 설명에 그치지 않고 핵심 로직(인증, 데이터 흐름, 에이전트 하네스)마다 정밀한 Mermaid 다이어그램을 병행 생성하여 인간 가독성과 에이전트 공간 추론력을 동시에 확보한다.

4. **Git Commit 기반의 시계열 자가 갱신 워크플로우 내재화**
   * 사용자가 코드를 수정하거나 저장소 작업 시, 현재 파일 스냅샷뿐 아니라 `git log`와 변경 diff를 대조하여 문서가 코드와 항상 동기화되도록 유지한다.
