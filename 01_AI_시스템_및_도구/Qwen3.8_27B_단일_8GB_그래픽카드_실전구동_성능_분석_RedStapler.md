# Qwen 3.8-27B 단일 8GB 그래픽카드 실전 구동 및 실측 성능 분석 — Red Stapler

## 💡 핵심 요약 (Level 0)
1. **단일 8GB VRAM(RTX 4060)에서 27B 원샷 구동 실증**: Unsloth IQ4_XS(약 14GB) 양자화 모델을 8GB GPU에 26개 레이어만 올리고 나머지 38개 레이어를 CPU로 오프로드하여, 70K 컨텍스트와 4-bit KV 캐시 환경에서 7GB VRAM 점유(OS 여유 1GB 확보) 상태로 구동에 성공했다.
2. **속도(4~5 tok/s)는 느리지만 결과물은 Claude Opus 4.6 압도**: 마인크래프트 3D, Three.js 네온 시티 등 고난도 원샷 웹 생성에서 20,000 토큰 이상의 심층 추론(Thinking)을 거쳐 에이전트 루프 없이 단번에 완성도 높은 결과물을 도출했다.
3. **CPU 오프로드 핵심 병목 및 비트 정렬 역설 규명**: 8GB 환경에서 3비트가 4비트보다 더 가벼움에도 불구하고, 2의 거듭제곱으로 나누어떨어지지 않는 비트 패킹 때문에 CPU 연산 시 정렬 페널티가 발생하여 4비트(IQ4_XS)보다 오히려 속도가 느려지는 현상을 실측 검증했다.

## 📜 상세 분석 및 타임스탬프 근거 (Level 1 Claims)

### 1. 8GB 환경 극한 튜닝 파라미터 구성 [00:00~02:30]
- **테스트 환경**: 단일 RTX 4060 8GB VRAM, 6코어 CPU.
- **모델 선택**: `Unsloth Qwen 3.8-27B IQ4_XS` (베이스 모델 대비 성능 하락폭 단 6%, 모델 크기 약 14GB).
- **VRAM 예산 배분**:
  - 컨텍스트 크기: 70K 토큰으로 실용적 제한.
  - KV 캐시: 4-bit 양자화 적용.
  - 레이어 오프로드: 64개 레이어 중 **26개 레이어만 GPU에 할당** ➔ GPU VRAM 약 7GB 점유 (윈도우 DWM/OS용 1GB 안전 마진 확보).
- **CPU 및 스레드 최적화**:
  - CPU 스레드 풀 크기를 물리적 코어 수와 1:1로 일치시킴 (6코어 CPU ➔ 6 스레드).
  - 투기적 디코딩: MTP(Multi-Token Prediction) 설정, 최대 드래프트 토큰 2개 적용.
- **추론(Thinking) 예산 해제 필수**:
  - Qwen 3.8은 생각의 깊이가 매우 깊어 중간 웹 생성 프롬프트 하나에만 **약 20,000 토큰의 Thinking을 소모**함.
  - 추론 예산(Reasoning Budget) 제한이 걸려 있으면 중간에 생각이 강제 중단되므로 무제한으로 풀어야 함.
- **샘플링 권장값 (Unsloth)**:
  `Temperature 1.0, Top-K 20, Repeat Penalty 1.0, Min-P 0.0`

### 2. 하네스(Harness) 타임아웃 트러블슈팅 [02:30~03:20]
- **경량 하네스(Pi) 채택**: 8GB에서는 프롬프트 오버헤드를 최소화하기 위해 시스템 프롬프트가 극도로 얇은 경량 하네스를 사용.
- **치명적 장애 및 해결**:
  1. *장애*: 1시간 동안 잘 쓰다가 쓰기 도구(Write tool call) 호출 도중 프로세스가 루프에 빠지거나 강제 종료됨.
  2. *원인*: 토큰 생성 속도가 초당 4~5토큰으로 너무 느려 기본 HTTP 클라이언트 타임아웃에 걸림. 또한 대형 파일 쓰기 시 출력 최대 토큰(Max output tokens) 제한에 걸림.
  3. *해결*: **하네스 설정에서 HTTP Timeout을 비활성화(무제한)하고, Output Max Token 한도를 대폭 증설**함.

### 3. 실전 4대 벤치마크 테스트 결과 [03:20~04:30]

| 테스트 과제 | 소요 시간 | 평균 토큰 속도 | 평가 및 비교 |
| :--- | :---: | :---: | :--- |
| **마인크래프트 3D 랜딩 페이지** | 약 2.5시간 | **4.2 tok/s** (초반 6 ➔ 후반 4) | 원샷 완결. Claude Opus 4.6 대비 3D 씬 디테일과 인터랙션 우수 |
| **사이버펑크 네온 시티 (Three.js)** | 약 1.5시간 | **5.0 tok/s** | 복잡한 3D 셰이더와 카메라 제어 코드 완벽 구동 |
| **개인 포트폴리오 웹사이트** | 약 2.0시간 | **4.6 tok/s** | 고밀도 프롬프트 기반 커스텀 레이아웃 및 반응형 완결 |
| **인테리어 디자인 랜딩 페이지** | 약 1.5시간 | **5.0 tok/s** | 상용 에이전시급 세련된 UI 구성 완성 |

### 4. 8GB vs 16GB 체급 판정과 3비트 역설 [04:30~05:13]
- **3비트(3-bit)의 역설**:
  - 메모리만 보면 3비트가 더 가벼워서 8GB에 유리할 것 같으나, **CPU 오프로딩 환경에서는 3비트가 4비트보다 훨씬 느림**.
  - 이유: 3비트는 2의 거듭제곱(2, 4, 8)으로 나누어떨어지지 않아 CPU의 SIMD 벡터 레지스터 및 캐시 라인 정렬(Alignment) 시 추가적인 비트 시프트/언패킹 오버헤드가 발생하기 때문.
- **체급별 최종 결론**:
  - **8GB GPU**: 원샷 품질은 Opus를 능가하나, 작업당 1.5~2.5시간이 걸리므로 일상 인터랙티브 용도로는 비실용적 (야간 배치 작업이나 단일 대작업 한정 유효).
  - **16GB GPU**: 70K 컨텍스트에서 **12~14 tok/s**가 나오므로 실전 일상 드라이버로 즉시 투입 가능.

## 🛠️ AI(나) 및 사용자 3-PC 환경 적용점 (Level 2 System Actions)

1. **메인 데스크톱 (Ildo 본체) 1:1 사양 매칭 검증**:
   - 본체 스펙: **AMD Ryzen 5 5600X (6코어 12스레드) + 32GB RAM + RX 6600 (8GB VRAM)**.
   - 본 영상의 테스트 환경(6코어 CPU + 8GB VRAM + 32GB RAM)과 **완벽히 동일한 물리적 구성**임.
   - **본체 구동 최적 레시피**:
     - 가중치: `Unsloth IQ4_XS` (3비트 금지, 4비트 고정).
     - 레이어 분할: GPU 26개 레이어 오프로드 (VRAM 7GB 점유, OS 1GB 보존).
     - 스레드 설정: CPU 스레드 6개 고정 (`-t 6`, 물리 코어 수 일치).
     - KV 캐시: `--cache-type-k q4_0 --cache-type-v q4_0`.
     - 투기적 디코딩: MTP n=2 적용.
2. **에이전트 하네스 HTTP 타임아웃 무력화 룰**:
   - 로컬 8GB 모델 연동 시 OpenCode, Ollama, 커스텀 에이전트에서 **HTTP Request Timeout을 반드시 0(무제한) 또는 3시간 이상으로 설정**해야 함.
   - Max output tokens 제한을 최소 32K 이상으로 확장하지 않으면 코드 생성 중 침묵 중단됨.
3. **서브 노트북 격리 헌법 재확인**:
   - 6코어 데스크톱에서도 4.2~5.0 tok/s로 2시간이 소요되므로, 저전력 인텔 i5 내장 그래픽 노트북에서는 절대 로컬 대형 모델을 돌리지 않고 클라우드 Gemini 3.8 Flash에 100% 집중하는 현 체제가 최적임을 재입증.
