# ⚡ Qwen 3.8-27B 단일 8GB VRAM 구동 및 최적화 하네스 완전 분석

## 📌 1. 핵심 요약 (3줄 압축)
1. **8GB VRAM에서 27B 모델 단일 구동 성공**: Unsloth IQ4_XS 양자화, 4-bit KV Cache, GPU 26레이어 오프로딩 조합으로 8GB 그래픽카드(RTX 4060 등)에서 Qwen 3.8-27B를 7GB VRAM 내로 안정 안착.
2. **사고(Thinking) 예산 제한 해제 & 타임아웃 해제 필수**: Qwen 3.8은 웹 생성 시 약 2만 토큰의 심층 추론을 수행하므로, 추론 예산(Reasoning Budget)을 풀고 HTTP 타임아웃을 비활성화해야 원샷 코드 작성이 중단 없이 완결됨.
3. **Claude Opus 능가하는 원샷 완성도**: 생성 속도는 4.2~5 tok/s로 1.5~2.5시간 소요되나 에이전트 루프 없이 단 한 번의 프롬프트로 Three.js 3D 씬과 웹사이트를 무결점으로 완성.

## ⚙️ 2. 8GB VRAM 극한 최적화 셋업 레시피

24GB VRAM 카드가 권장되는 27B 모델을 8GB VRAM 환경에서 구동하기 위한 세부 설정 파라미터는 다음과 같다.

| 항목 | 설정값 | 최적화 목적 및 비고 |
| :--- | :--- | :--- |
| **모델 포맷** | **Unsloth IQ4_XS** | 원본 대비 성능 저하 6% 미만, 크기 14GB로 압축 |
| **컨텍스트 크기** | **70K 토큰** | 소규모 프로젝트 및 원샷 웹 개발에 충분한 용량 |
| **KV Cache 양자화** | **4-bit (q4_0)** | 컨텍스트 길이에 따른 VRAM 급증 억제 |
| **GPU 레이어 오프로드** | **26개 레이어** | VRAM 약 7GB 점유 (OS 및 디스플레이 여유 1GB 확보) |
| **CPU 스레드 풀** | **물리 코어 수 일치** | 6코어 CPU 기준 6스레드 할당으로 CPU 오프로드 가속 |
| **추측 디코딩 (Speculative)** | **MTP (2 max draft tokens)** | 다중 토큰 예측으로 추론 속도 보정 |
| **사고 모드 (Thinking)** | **Enable Thinking (ON)** | 심층 논리 추론 활성화 |
| **추론 예산 (Reasoning Budget)** | **무제한 (Budget 제거)** | 중간 생각 중단(Abort) 방지 (웹 생성 시 약 2만 토큰 사고) |
| **샘플링 파라미터** | Temp 1.0, Top-K 20, Rep. Penalty 1.0, Min-P 0.0 | Unsloth 공식 권장 샘플링 프리셋 |

## 🛠️ 3. 에이전트 하네스 & 시스템 타임아웃 튜닝

8GB 카드 환경은 토큰 생성 속도가 느리기 때문에 일반적인 에이전트 프레임워크 사용 시 타임아웃 오류가 발생한다.

1. **초경량 하네스 선택 (Pi Harness)**:
   - 시스템 프롬프트가 과도하게 큰 프레임워크 대신 컨텍스트 낭비가 적은 경량 하네스를 사용.
2. **HTTP 타임아웃 비활성화 (Disable HTTP Timeout)**:
   - 초당 4~5 토큰 속도로 긴 코드를 작성할 때 툴 호출이 타임아웃으로 끊기는 현상을 방지.
3. **최대 출력 토큰(Max Output Tokens) 증설**:
   - 단일 파일 작성이 길어질 때 중간에 잘리지 않도록 출력 버퍼를 충분히 확장.

## 📊 4. 실전 원샷 벤치마크 테스트 결과

에이전트 루프나 수동 수정 없이 단일 프롬프트(One-shot)로 생성한 결과:

1. **Minecraft 3D 랜딩 페이지**:
   - 소요 시간: 약 2시간 30분
   - 평균 속도: 4.2 tok/s (초기 6 tok/s에서 컨텍스트 증가 시 감소)
   - 결과: Claude Opus 4.6 결과물과 대등하거나 능가하는 3D 인터랙션 구현
2. **Three.js 기반 Cyberpunk 네온 시티 3D 씬**:
   - 소요 시간: 약 1시간 30분
   - 평균 속도: 약 5 tok/s
3. **개인 포트폴리오 웹사이트 (고상세 프롬프트)**:
   - 소요 시간: 약 2시간
   - 평균 속도: 약 4.6 tok/s
4. **인테리어 디자인 랜딩 페이지**:
   - 소요 시간: 약 1시간 30분
   - 평균 속도: 약 5 tok/s

## 💡 5. 사용자 하드웨어(RX 6600 8GB + 5600X) 및 실무 시사점

1. **사용자 메인 데스크톱 사양과의 완벽 일치**:
   - 사용자 메인 PC(AMD Ryzen 5 5600X 6코어 / RX 6600 8GB VRAM / 32GB RAM) 환경과 완전히 동일한 아키텍처 스펙.
   - GPU 26레이어 + CPU 6스레드 + 32GB 시스템 메모리 분할을 적용하면 데스크톱 로컬에서 27B 모델 완전 구동 가능.
2. **왜 3-bit(IQ3)가 아닌 4-bit(IQ4_XS)를 쓰는가?**:
   - CPU로 무겁게 오프로딩할 때, **2의 배수가 아닌 비트 양자화(3-bit 등)는 CPU AVX/SIMD 연산 시 추가 디코딩 오버헤드가 발생하여 4-bit보다 속도가 오히려 느려짐**.
3. **실무 활용 가이드**:
   - **일상 작업**: 초고속 즉시 응답이 필요한 코딩은 클라우드 Gemini 3.7 Flash 우선 활용.
   - **완전 오프라인/프라이빗 심야 배치 작업**: 네트워크가 차단된 환경이거나 비공개 코드를 대규모로 작성할 때 밤새 돌려두는 무인 로컬 코드로 유용.
   - **서브 노트북(Dell Latitude 7440)**: 외장 VRAM이 없으므로 배터리 및 발열 방지를 위해 클라우드 추론 원칙 엄수.
