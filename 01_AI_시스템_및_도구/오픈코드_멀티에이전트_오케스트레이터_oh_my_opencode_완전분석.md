## 💡 핵심 3줄 요약 (Level 0)

1. **oh-my-opencode의 정체성**: 오픈코드(OpenCode) 에디터 환경에서 GPT, Claude, Gemini, Grok 등 다중 상용 모델을 팀원처럼 묶어 자동 라우팅·병렬 실행하는 오픈소스 오케스트레이터(GitHub 10,000+ Star).
2. **역할별 최적 분담**: 설계(GPT-5.2), 프론트엔드(Gemini 3), 문서·코드 탐색(Claude Sonnet), 초고속 연산(Grok) 등 모델별 특기 영역을 자동 디스패치하며 중단 시 강제 재실행 루프 지원.
3. **치명적 트레이드오프**: 백지 상태의 신규 프로젝트 구축에는 압도적 속도를 내지만, 대규모 병렬 호출로 인한 **극심한 토큰 과금**, Claude 계정 밴 위험, 기존 코드 유지보수 시 과도한 수정(Over-engineering) 리스크 존재.

## 📜 핵심 주장 및 타임스탬프 근거 (Level 1 Claims)

* **다중 모델 특기별 자동 디스패칭**:
  단일 LLM에 모든 작업을 맡기지 않고 설계, UI, 분석, 탐색에 맞춰 최적의 모델(GPT, Gemini, Sonnet, Grok)을 자동으로 분기 호출.
* **무중단 강제 재실행(Resilient Execution)**:
  에이전트가 중간에 타임아웃이나 오류로 멈출 경우 프로세스를 감지해 자동으로 복구 및 재실행.
* **Greenfield vs Brownfield 불균형**:
  아무것도 없는 백지 상태(Greenfield)에서는 높은 완성도를 보이나, 기존 완성된 프로덕션 코드를 정밀 수정(Brownfield)할 때는 불필요하게 넓은 범위를 건드리는 비효율 발생.
* **비용 및 정책 리스크**:
  병렬 토큰 소모량이 막대하며 서드파티 래퍼 연동 시 플랫폼 계정 차단 정책에 노출될 수 있음.

## 🧠 원자적 지식 카드 (Level 2)

* **개념 1: 모델 라우팅 오케스트레이션(Model Routing Orchestration)**  
  단일 LLM에 종속되지 않고 작업 특성(설계, UI, 리서치, 디버깅)에 따라 최적의 모델 API로 분기 실행하는 상위 제어 계층.
* **개념 2: 병렬 에이전트 토큰 증폭(Parallel Token Amplification)**  
  다수의 에이전트가 백그라운드에서 동시 추론할 때 컨텍스트가 복제·증폭되어 API 호출 비용이 기하급수적으로 증가하는 현상.
* **개념 3: 외과수술적 수정(Surgical Edit) vs 전면 재작성(Full Rewrite)**  
  기존 프로젝트 유지보수 시에는 전체 파일을 다시 쓰는 에이전트보다 정확한 변경 블록만 치환하는 외과수술적 수정이 회귀 버그와 비용을 차단하는 정석.

## ⚖️ 5-Gate 판별 및 의사결정 (Level 3+)

1. **실제 문제인가?**: YES (물리적 다중 모델 라우팅과 병렬 분산 실행은 Antigravity의 '단일 모델 논리적 역할 분리'와 다른 미검증 기술 영역).
2. **기존 기능으로 해결 가능한가?**: PARTIAL (Antigravity는 단일 Gemini 기반 5대 논리적 역할 분리로 높은 토큰 효율을 보이나, 이종 모델 간 실제 물리적 병렬 오케스트레이션은 미도입 영역).
3. **자동화할 가치가 있는가?**: YES (특정 고부하·신규 작업에서 실질적 속도/품질 향상 가능성 탐색 가치 있음).
4. **추가 복잡성보다 효과가 큰가?**: **검증 필요 (Unverified)** (대규모 병렬 토큰 과금 및 제어권 중복 위험이 상존하므로 실측 필수).
5. **쉽게 삭제 가능한가?**: YES (별도 Sandbox 디렉터리에 격리 설치 시 메인 시스템 영향도 제로).
