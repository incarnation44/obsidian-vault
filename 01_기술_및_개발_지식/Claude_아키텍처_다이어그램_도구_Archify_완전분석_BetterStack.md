# 🎬 Claude 아키텍처 다이어그램 생성 오픈소스 도구 Archify 완전분석 (Better Stack)

## 💡 핵심 3줄 요약
1. **아키텍처 맵의 LLVM 구조**: AI 에이전트가 직접 그림이나 좌표를 그리는 대신 정형화된 **Typed JSON(중간 표현, IR)**만 출력하고, 엄격한 스키마 검증기(Validator)를 통과한 데이터만 로컬 컴파일러가 인터랙티브 HTML로 렌더링하는 'Fail-Closed' 아키텍처를 채택했다.
2. **코드 증거(Repo Evidence) 바인딩**: 각 노드는 실제 Git 커밋 SHA 및 코드 라인 번호에 증거가 연결되어야만 `SRC` 인증 배지를 획득하며, 코드상에서 증명되지 않는 허구의 컴포넌트(Kafka, Redis 등 환각)를 원천 배제한다.
3. **인터랙티브 탐색 & PR Diff 스냅샷**: 상하류(Upstream/Downstream) 의존성 경로 탐색 및 애니메이션 실행이 가능하며, 코드 변경 전후의 아키텍처 JSON 스냅샷을 비교(Diff)하여 추가·삭제·재배치된 컴포넌트만 시각적으로 추적할 수 있다.

## 📌 주요 내용 및 타임스탬프 포인트
- **[00:00 ~ 01:13] AI 다이어그램의 고질병과 Archify의 등장**:
  - 기존 에이전트에게 리포지토리 분석을 맡기면 없는 서비스(Kafka, Redis 등)를 날조하거나 읽기 힘든 복잡한 쓰레기 그림을 생성하는 문제 해결.
  - Claude Code, Cursor, Codex 등에 스킬(Skill) 형태로 즉시 연동되어 수개월 만에 44,000 스타 달성.
- **[01:13 ~ 02:40] 프롬프트 원칙과 'Repo Evidence' 검증 루프**:
  - **1 Question = 1 Diagram 원칙**: "전체 코드 다 그려줘"는 무조건 실패함. "캐시 미스 시 어떤 일이 일어나는가? 8~12개 노드 제한, 코드에 증명 안 되는 컴포넌트는 생략"처럼 뾰족한 질문 1개만 던져야 함.
  - **Repo Evidence 바인딩**: 노드마다 실제 Git 커밋과 코드 라인 범위가 지정되어, 근거가 없으면 검증 단계에서 탈락.
- **[02:40 ~ 03:33] 인터랙티브 탐색과 대화형 아키텍처**:
  - 정적 이미지나 복잡한 화살표를 눈으로 좇는 대신, 특정 노드를 클릭해 업스트림/다운스트림 의존성을 즉시 하이라이트하고 데이터 흐름(Route)을 시각적으로 재생.
  - 고화질 PNG 및 공유 카드(Share Card)로 정밀 내보내기 지원.
- **[03:33 ~ 04:33] PR 코드 리뷰를 위한 아키텍처 Diff**:
  - 변경 전 JSON과 변경 후 JSON 스냅샷을 비교하여 추가(added), 제거(removed), 리라우팅(rerouted)된 의존성 변경분만 시각적 Diff로 출력.
  - 아키텍처 명세를 JSON으로 Git에 커밋함으로써 다음 에이전트 세션에서도 일관된 구조 계승.
- **[04:33 ~ 05:30] 시스템 설계 철학 (LLVM for System Maps)**:
  - 프론트엔드 = 코딩 에이전트 / IR = Typed JSON / 컴파일러 = HTML 렌더러.
  - **레이아웃 제어 분리**: AI 모델은 박스의 물리적 위치를 결정하지 못하며 오직 시스템의 관계와 의미만 기술함 (레이아웃은 컴파일러가 자동 최적화).
  - 5가지 모드 지원: Architecture, Workflow, Sequence, Data Flow, Lifecycle.
- **[05:30 ~ 07:20] 사용 가이드라인 및 한계점**:
  - README 내 단순 마크다운 삽입이 목적이라면 여전히 Mermaid가 유리할 수 있음.
  - Archify는 PR 리뷰, 설계 문서(Design Doc), 디버깅 경로 검증 등 **에이전트가 생성한 아키텍처 산출물의 무결성을 검증**할 때 최적의 성능 발휘.

## 🛠️ AI(나)에게 적용할 점
- **The Loupe 검증 루프와의 결합 (Typed IR & Grounding)**:
  - Antigravity의 다이어그램 생성 스킬(`diagram-design`) 및 아키텍처 문서화 시, AI가 직접 복잡한 시각 레이아웃을 생성하려 하지 않고 **중간 JSON 규격을 먼저 검증(Fail-Closed)한 뒤 렌더링하는 파이프라인**을 적극 벤치마킹함.
- **코드 증거(Repo Evidence) 바인딩 의무화**:
  - 아키텍처 분석이나 기능 설명 시 추상적 개념 나열을 금지하고, 실제 코드의 `[파일명#L라인]` 링크를 노드/팩트에 1:1 결합하는 그라운딩 원칙을 철저히 유지.
- **1 Question = 1 Diagram & 8~12 노드 상한선**:
  - 거대한 전체 시스템을 한 번에 그리려다 발생하는 토큰 낭비와 환각을 차단하고, 특정 비즈니스 흐름(예: 캐시 미스, 인증 실패, 결제 트랜잭션 등) 단위로 쪼개어 시각화함.
