# 8GB VRAM의 실질 마지노선 6GB 법칙

## 1. 개념 정의
8GB VRAM을 가진 GPU(예: RTX 3070, RX 6600 등)에서 로컬 AI 모델을 구동할 때, **모델의 순수 가중치(Weight) 파일 크기는 반드시 6GB를 넘지 않아야 한다**는 하드웨어 운용 법칙이다.

---

## 2. 왜 6GB인가? (나머지 2GB의 행방)
흔히 초보자들이 8GB VRAM에 7.5GB짜리 모델 파일을 올려놓고 "안전하게 들어갔다"고 착각하지만, 추론(Inference)이 시작되면 시스템은 두 가지 추가 공간을 맹렬히 요구한다.

1. **KV 캐시 (Key-Value Cache)**: 사용자가 입력한 프롬프트와 모델이 생성한 답변의 맥락을 기억하는 임시 작업 공간. 8K ~ 32K 컨텍스트를 열어두면 이 공간만 1~2GB를 쉽게 집어삼킨다.
2. **런타임 오버헤드 (Runtime Overhead)**: 모델 구동기(llama.cpp, LM Studio 등) 자체가 차지하는 메모리와 그래픽 카드 기본 유지 메모리(디스플레이 출력 등).

즉, 가중치가 6GB를 초과하면 대화를 시작하자마자 VRAM의 100% 한계치(8GB)를 치게 된다.

---

## 3. VRAM을 초과했을 때 일어나는 재앙 (PCIe 스왑)
VRAM이 꽉 찼다고 해서 곧바로 프로그램이 튕기는(OOM) 것은 아니다. 
최신 추론 엔진들은 똑똑하게(그리고 사용자 모르게) 초과된 데이터를 메인보드의 일반 시스템 RAM으로 오프로딩(Offloading)해 버린다.

- **VRAM 내 구동 시**: GPU의 초고속 메모리 대역폭(수백 GB/s)을 온전히 누리며 초당 50~60 토큰의 쾌적한 속도를 낸다.
- **RAM 스왑 발생 시**: GPU가 PCIe 대역폭의 좁은 병목을 뚫고 느려터진 시스템 RAM에서 데이터를 가져와야 한다. 이때 속도는 초당 2 토큰 이하로 **수직 낙하(최대 30배 성능 붕괴)**한다.

---

## 4. 실무 적용 지침
- 8GB VRAM 유저가 모델(.gguf 파일)을 고를 때, **파일 용량이 6.0GB를 초과한다면 그 모델은 '단일 구동용(No-Offload)' 리스트에서 기계적으로 제외**해야 한다.
- 용량이 6GB 미만인데 성능이 좋은 모델(예: `Qwen 3.5 9B Q4_K_M`)을 고르는 것이 8GB 세팅의 알파이자 오메가다.
- 만약 불가피하게 6GB가 넘는 대형 모델(35B 이상)을 써야 한다면, 대화형 속도(Latency)를 포기하고 명시적인 CPU 하이브리드 오프로딩 세팅([[KV_캐시_양자화와_MoE_특화_CPU_오프로딩]])을 통해 백그라운드 배치 작업으로 돌려야 한다.
