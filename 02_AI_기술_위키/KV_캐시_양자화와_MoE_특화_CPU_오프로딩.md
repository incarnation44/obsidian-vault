# KV 캐시 양자화와 MoE 특화 CPU 오프로딩 (8GB VRAM 최적화)

## 1. 개요
8GB VRAM이라는 물리적 한계 안에서 30B 체급 이상의 모델을 실사용 가능한 속도(15~20 tok/s)와 컨텍스트(100K+)로 구동하기 위한 llama.cpp의 핵심 튜닝 기법이다. 무작정 모델 가중치를 양자화하는 것을 넘어, **'메모리 사용의 구조적 병목(MoE 레이어, KV 캐시)'을 타겟팅**하여 최적화하는 것이 핵심이다.

---

## 2. 핵심 튜닝 기법

### 1) MoE (Mixture of Experts) 특화 CPU 오프로딩
- **원리**: MoE 모델은 거대한 파라미터(예: 35B)를 가지지만, 특정 토큰 하나를 추론할 때 활성화되는 파라미터(예: 3B)는 극히 일부인 '전문가(Experts)' 네트워크로 이루어져 있다.
- **적용**: 40개의 신경망 레이어를 통째로 GPU에 올리려다 메모리 초과로 크래시를 내는 대신, 시스템 RAM(CPU)으로 용량이 크고 드문드문 호출되는 전문가 레이어 수십 개를 명시적으로 떠넘긴다.
- 남은 GPU VRAM(예: 7.9GB) 공간에는 빈번하게 호출되는 코어 어텐션 레이어를 꽉 채워 연산 병목을 제거한다.

### 2) KV 캐시 양자화 (KV Cache Quantization)
- **원리**: LLM은 이전 대화 내용(Context)을 기억하기 위해 Key-Value(KV) 행렬을 VRAM에 캐싱해 둔다. 모델 가중치를 아무리 압축해도, 컨텍스트가 10K, 50K로 길어지면 이 KV 캐시 자체가 수 GB의 VRAM을 먹어치워 시스템을 터뜨린다.
- **적용**: llama.cpp의 플래그 `-ctk q4_0` (Key 캐시 4-bit 양자화)와 `-ctv q4_0` (Value 캐시 4-bit 양자화)를 적용한다.
- **효과**: 캐시가 차지하는 메모리 부피가 절반 이하로 급감한다. 8GB VRAM 환경에서도 VRAM 크래시나 RAM 스와핑 지연 없이 100K 이상의 방대한 컨텍스트(회의록, 긴 코드 파일)를 메모리에 띄울 수 있다.

---

## 3. 실무 적용 시의 트레이드오프 (ADR 기반)

이 기법은 '구동 불가'를 '쾌적한 구동'으로 바꾸는 흑마법이지만, 품질 저하라는 뚜렷한 반대급부가 존재한다.

- **장점 (Capacity & Speed)**: 8GB VRAM 유저가 35B 체급을 체감 속도 저하 없이 쓸 수 있다. 대용량 텍스트 번역, 회의록 요약, 브레인스토밍에서 압도적 가성비를 낸다.
- **단점 (Logic Hallucination)**: 모델 자체도 Q4로 압축된 마당에, 과거 대화를 기억하는 뇌세포(KV 캐시)마저 Q4로 압축하면 정밀도가 떨어진다. 수천 줄의 코드에서 특정 변수명을 정확히 추적해야 하는 디버깅 작업 시, 캐시 손실로 인한 환각(Hallucination) 빈도가 눈에 띄게 증가한다.
- **판단 기준**: 
  - 📝 **문서 요약 / 창작**: 35B MoE + KV 캐시 양자화 적용 (넓고 얕은 컨텍스트 허용).
  - 💻 **정밀 코딩 / 디버깅**: 8B 단일 모델 + 온전히 VRAM 적재 + FP16 KV 캐시 유지 (좁고 깊은 무손실 컨텍스트 유지).
