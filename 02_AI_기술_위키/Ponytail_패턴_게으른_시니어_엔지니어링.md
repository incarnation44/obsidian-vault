# Ponytail 패턴 (게으른 시니어 엔지니어링)

AI 코딩 에이전트가 불필요하게 긴 코드를 작성하거나 이미 존재하는 바퀴를 재발명하지 않도록, **"가장 게으른 시니어 개발자"의 사고방식을 강제 주입하는 에이전트 프롬프트 및 스킬 패턴**이다.

## 🎯 3대 선제 검증 질문 (Core Triage)

에이전트가 코드 생성 도구를 호출하기 전 반드시 통과해야 하는 3가지 질문:

1. **필요한가? (Is it necessary?)**:
   - 사용자가 요청한 목표 달성에 이 기능/코드가 진짜 필수적인가?
   - 가상의 미래 확장성을 핑계로 오버엔지니어링하고 있지 않은가?
2. **이미 있나? (Does it already exist?)**:
   - 웹 표준(HTML5/CSS3), 언어 내장 표준 라이브러리, 이미 설치된 패키지에 있는가?
   - 기존 코드베이스에 동일한 역할을 수행하는 헬퍼 함수나 유틸리티가 이미 존재하는가?
3. **한 줄로 되나? (Can it be a one-liner?)**:
   - 복잡한 알고리즘이나 상태 머신 대신 표준 API 선언 한 줄로 종결할 수 있는가?

---

## 📊 실측 벤치마크 효과 (Solostack 검증)

- **테스트 환경**: 동일 리포지토리의 동일 이슈 티켓 3개, Claude Haiku 모델 기준.
- **코드 생성량**:
  - 스킬 OFF: 평균 539줄
  - 스킬 ON: 평균 112줄 (**약 79% 코드 다이어트**)
- **토큰 비용 절감**: 약 38% 절감.
- **결정적 사례**:
  - 컬러 피커(Color Picker) 기능 구현 요청 시:
    - **스킬 OFF**: 색상 변환 함수, 팝업 상태 제어 등 242줄의 JS/CSS 코드를 자체 제작함.
    - **스킬 ON**: HTML5 표준 `<input type="color">` 태그 한 줄을 포함해 전체 20줄로 즉시 종결.

---

## ⚠️ 한계 및 적용 경계
- **미세 버그 수정(Small Fixes)**: 단순 오타 수정이나 기존 함수의 한두 줄짜리 패치에는 스킬 적용 전후 코드 차이가 거의 없다.
- **신규 기능 추가(Feature Implementation)**: 새로운 컴포넌트나 파이프라인을 추가할 때 불필요한 보일러플레이트를 걸러내는 데 가장 강력한 위력을 발휘한다.
