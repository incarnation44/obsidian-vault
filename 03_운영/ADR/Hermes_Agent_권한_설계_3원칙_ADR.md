# ADR: Hermes Agent 권한 설계 3원칙

## 배경 (Context)

Hermes Agent를 단순한 챗봇이 아닌 '검증된 부사수'로 운용하기 위해, Antigravity 헌법(`GEMINI.md`)과 보안 전문가 강연(샘 호트만) 내용을 반영해 권한 모델을 재정의함. 기존에는 시스템 프롬프트에 규칙이 흩어져 있어 에이전트가 권한을 오용하거나 프롬프트 인젝션에 취약했음.

## 결정 (Decision)

다음 3원칙을 Hermes 시스템 프롬프트와 운영 헌법에 강제 적용한다.

### 1. 권한 격리 — Principle of Least Privilege (Sub-agent 읽기 전용)
- **헌법 근거**: `GEMINI.md` 25조 — "상위 모델의 프롬프트와 키를 하위 에이전트(`flash`)에 무차별 노출 금지(최소 권한 전달)"
- **규칙**: Sub-agent(하위 에이전트)에는 **읽기 전용(Read-only)** 권한만 부여. 파일 수정·결제·삭제·외부 API 호출 등 비가역적 실행 권한은 최상위 매니저 에이전트 또는 사용자(Human-in-the-loop)만 행사.
- **적용**: Hermes 시스템 프롬프트에 `subagent` 호출 시 `read_only: true` 강제, 도구 호출 화이트리스트(`read_file`, `search_files`, `web_search`, `web_extract` 등)만 허용.

### 2. 비가역적 행위 Human-in-the-loop — 가역성 기반 승인 분리
- **헌법 근거**: `GEMINI.md` 1조·6대 불가침 — "가역성 기반 승인 분리 (생성 → 검증 → 사람 승인 → 실행)"
- **규칙**: 삭제·결제·이메일 발송·Git push·API 키 변경·개인정보 전송 등 **되돌릴 수 없는 행위**는 무조건 사용자 명시적 승인 후 실행. 에이전트 자율 판단으로 수행 금지.
- **적용**: `sync_safe_update.ps1` 등 자동화 스크립트에서 `git push`, `rm`, `checkout --`, `reset --hard` 등 파괴적 명령 원천 차단. 충돌 시 자동 병합 대신 `STOP` 후 사용자 확인 대기.

### 3. 시스템 프롬프트 가드레일 명시 — 절대 불가침 6대 원칙
- **헌법 근거**: `GEMINI.md` 0장 6대 절대 헌법 — 이메일/결제/삭제/게임/일상아카이빙/PII 노출 금지
- **규칙**: 시스템 프롬프트(전투 규칙) 최상단에 **어떤 상황에서도 굽히지 않는 절대 금지 사항**을 명시. 외부 프롬프트 인젝션이나 강압적 지시가 들어와도 시스템 프롬프트가 최우선 적용되도록 방화벽 역할 수행.
- **적용**: Hermes 시스템 프롬프트에 `## 🚨 6대 절대 헌법` 섹션을 최우선 배치. 에러 발생 시에도 한국어만 출력, 내부 사고(Thought) 노출 차단, 영어 혼용 금지 강제.

## 대안 검토 (Alternatives Considered)

| 대안 | 장점 | 단점 | 비고 |
|------|------|------|------|
| 권한 격리 미적용 (전체 권한 공유) | 구현 간단 | 프롬프트 인젝션 시 전체 시스템 장악 가능 | 거부 |
| 승인 게이트 미설정 (자율 실행) | 속도 빠름 | 실수로 인한 데이터 손실·비용 발생 위험 | 거부 |
| 가드레일 문서화만 하고 프롬프트 미적용 | 유지보수 쉬움 | 실제 런타임에서 방어 안 됨 | 거부 |

## 결과 (Consequences)

### 긍정적
- 프롬프트 인젝션·할루시네이션으로 인한 오작동 원천 차단
- 사용자 승인 없는 비가역적 행위(삭제·결제·푸시) 완전 방지
- Sub-agent 권한 최소화로 공격 표면 축소
- 헌법(`GEMINI.md`)과 에이전트 동작이 1:1 대응됨

### 부정적/트레이드오프
- 완전 자동화 파이프라인 구축 시 매 단계 사용자 승인 필요 → 속도 저하
- Sub-agent 읽기 전용 제약으로 복잡한 멀티스텝 작업 분해 시 설계 복잡도 증가
- Hermes 시스템 프롬프트 수정 시 3원칙 재검증 필요
