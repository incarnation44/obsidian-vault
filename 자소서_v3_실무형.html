지원 동기

가장 결정적인 이유는 기술의 이동성이었습니다. 장사는 가게가 있어야 하지만 개발은 어디서든 할 수 있습니다. 저는 영어를 실생활에서 사용해 온 덕분에 국내뿐 아니라 해외 환경에서도 일하는 데 언어 장벽이 없습니다. 기술과 언어가 결합되면 무대를 선택할 수 있다는 판단이 이 방향을 확신하게 만들었습니다.

KH정보교육원에서 6개월간 집중적으로 공부하면서 방향이 맞다는 걸 확인했습니다. 구조를 설계하고 오류를 추적하는 과정이 적성에 맞았고, 배울수록 모르는 게 더 많아지는 분야라는 점이 오히려 동기가 됩니다.

성격의 장단점
장점 — 지속성과 문제 추적

10년 넘게 하루 15시간씩 가게를 운영한 경험은 컨디션이나 감정에 관계없이 일을 이어가는 체질을 만들었습니다. 개발 공부에서도 이해가 안 되는 부분을 그냥 넘기지 못합니다. 답이 나올 때까지 쪼개서 확인하는 것이 저의 방식입니다.

단점 — 보완 중

완성도에 집착해 시작을 늦추는 경향이 있습니다. 장사할 때도 준비가 충분하지 않으면 미루다 타이밍을 놓친 적이 있습니다. 지금은 일단 동작하는 것부터 만들고 점진적으로 개선하는 방식을 훈련 중입니다.

프로젝트 및 실무 적용

수료 전 진행한 팀 프로젝트에서는 백엔드 API 설계와 데이터베이스 연동을 담당했습니다. 컨트롤러-서비스-리포지토리 계층 구조로 기능을 분리하여 구현했으며, 회원 관리, 로그인(세션), 게시판 CRUD, REST API 등을 직접 개발했습니다.

프로젝트 중 데이터가 저장되지 않는 문제가 발생했을 때, 감이 아닌 흐름 추적으로 해결했습니다. 요청값 → 서비스 로직 → 엔티티 매핑 → 쿼리 순서로 단계별로 확인하며 원인을 좁혔습니다. 이 방식이 장사할 때 "어디서 손실이 나는지 먼저 파악한다"는 습관과 같다는 것을 느꼈습니다.

팀 협업에서는 Git 브랜치를 나눠 작업하면서 충돌이 발생했을 때 혼자 덮어쓰지 않고 팀원과 소통해서 정리했습니다. 10년간 직원들과 함께 일하면서 얻은 소통 감각이 개발 협업에서도 동일하게 작동했습니다.

입사 후 포부

처음 6개월은 조직의 코드 구조와 개발 방식을 빠르게 익히는 데 집중하겠습니다. 모르는 게 생기면 스스로 파악하고 정리해서 질문하는 방식으로 팀에 부담을 최소화하겠습니다. 이미 완전히 낯선 분야에서 처음부터 시작해 본 경험이 있어, 새 환경 적응에 대한 막연한 불안은 없습니다.

1~2년 후에는 자바 스프링 백엔드를 독립적으로 설계하고 성능 문제를 직접 다룰 수 있는 개발자가 되는 것이 목표입니다. 장기적으로는 영어 역량을 살려 글로벌 팀과의 협업이나 해외 근무에도 기여할 수 있는 개발자가 되고 싶습니다. 저는 지금 어디서든 일할 준비가 되어 있습니다.
